# State, availability and acceptance

Read the owner that creates observable reference state and trace bindings through the feature. Separate durable state from drafts and derived values. Check availability against each target; do not import the newest template settings. Use semantic controls, stable identity and recoverable errors. Select Swift Testing for logic and XCTest for UI boundaries. Verify compact/regular layouts when supported; report manual VoiceOver checks separately.

Authority: [State, availability and acceptance](https://developer.apple.com/documentation/swiftui/managing-model-data-in-your-app). Documentation informs correctness; it is not evidence that this workflow ran successfully in an installed client.
