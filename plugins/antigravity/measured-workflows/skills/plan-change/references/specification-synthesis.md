# Specification Synthesis

Use this reference when interviews, issues, repository evidence, and existing decisions must become one implementation specification.

- Trace every requirement to an observed source or ratified decision.
- Separate required behavior, constraints, non-goals, assumptions, and unresolved questions.
- Define interfaces, states, errors, data authority, compatibility, and acceptance evidence precisely enough to test.
- Resolve discoverable conflicts; present decision-owner conflicts instead of silently choosing.
- Keep proposed architecture separate from approved scope.

The result is decision-ready only when an implementer can act without inventing material product or authority decisions.
