# Compatibility and evidence preflight

Before a change, read the project's actual compiler, SDK, minimum OS, language mode, isolation, and selected scheme. An availability branch does not make an absent SDK symbol compile. Keep older targets and supported fallbacks unless the task explicitly changes them.

For editable collections preserve stable record IDs, numeric drafts, selection, focus, and explicit Save/Cancel semantics. Distinguish custom Binding setter behavior from onChange, including equal-value and programmatic writes. Route durable writes through the existing owner.

Verify short/wide layouts, keyboard obstruction, Dynamic Type, localization, and accessible alternatives to dragging. An observed object injected through the environment is not by itself a performance defect; measure its read/write dependencies.

Report SDK inspection, compilation, simulator journeys, manual accessibility, physical-device behavior, signed archives, and provider acceptance separately. An unavailable check is blocked or not run, never a pass. A present empty UILaunchScreen dictionary is valid metadata; a local build cannot establish provider acceptance.

Load only locally available reference files. Project packages do not inherit another skill's references merely because the skill is named. Keep future SDK and beta findings provisional until exact-version probes pass.
